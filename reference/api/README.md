# API reference — synced from the backend handoff

These files are **generated by the backend and copied here**; they are not edited
in this repository. The canonical source is
`frappe-bench/apps/yob_storefront/frontend-api-handoff/` in the backend repo, and
the full package (markdown + OpenAPI + Postman + examples) is mirrored at
[`docs/api-handoff/`](../../docs/api-handoff/).

| File | Version | Contents |
|---|---|---|
| `openapi.json` | **3.4.0** | every whitelisted storefront/auth endpoint, including the Phase 24B variant contract |
| `postman_collection.json` | 3.4.0 | runnable requests, including the family → resolve → add-to-cart flow |
| `live/` | 2.0.0 (**superseded**) | a 2026-08-13 response capture, kept for history only |

## What changed in 3.4.0 (Phase 25C)

* `cms.get_menu` — **new**. Published navigation tree, max two levels, with
  normalised destinations (type + public slug, never a database id).
* `cms.get_page` — **new**. A published page as ordered, discriminated blocks.
  Contains customer-priced Product Grid cards: **never cache across users**.
* `catalog.get_category_filters` — **new**. Facets for a category, from that
  category's own Filter Set only. No counts.
* `catalog.get_items` — additive `storefront_filters` parameter: OR within a
  filter, AND across filters, and part of the cursor binding.

## What changed in 3.3.0 (Phase 23B-5U / 24B / 24D-1)

* `catalog.resolve_variant` — **new**. `GET`, `template` + JSON-encoded
  `attributes` + `qty`; returns the shared product-detail payload.
* `catalog.get_item` — two discriminated modes (`is_template` 0 or 1); a family
  carries `attributes[]` + `variants[]` and no price.
* `catalog.get_items` — published for the first time (it shipped in Phase 22B);
  one card per simple Item and one per family, with `has_variants` and
  `price_state`.
* `cart.add_to_cart` — documents the server-side SKU revalidation and its
  refusals (`item_is_template`, `item_not_purchasable`, `item_not_found`).
* Selling UOM fields (`uom`, `stock_uom`, `conversion_factor`, `stock_qty`) on
  every priced payload.

**Valid variant combinations come only from `variants[]`.** Attribute values are
global in ERPNext, so a cross-product of `attributes[].values` invents
combinations nobody can buy. Never construct an item code in the browser.

A backend test (`test_response_contract.TestPublishedApiReference`) fails if a
whitelisted endpoint or a published error code is missing from this package.
